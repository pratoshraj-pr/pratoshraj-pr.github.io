Fundamentals of Generative vs Discriminative Modeling#

TL;DR

  • The cleanest way to separate the two is one question: which distribution is the model learning? A discriminative model learns \(P(\text{y}\mid\text{x})\). A generative model learns the joint \(P(\text{x},\text{y})\), usually as \(P(\text{x}\mid\text{y})\,P(\text{y})\).
  • Both are trained by the same principle, maximum likelihood, which approximately minimizes a KL divergence to the true distribution. Only the quantity inside the likelihood changes.
  • A generative model can classify (through Bayes’ rule) and sample new inputs. A discriminative model can only give you labels for inputs you already have.
  • The price of going generative is modeling \(P(\text{x}\mid\text{y})\), which is intractable without simplifying assumptions. Naive Bayes is the simplest such simplification.

Introduction#

The most common answer to “What is the difference between discriminative and generative models?” is: discriminative models learn the boundary, generative models learn the data distribution.

It is correct, and it is also one of those answers we can recite without really understanding it. It also opens a lot of questions:

  1. What does “learning the distribution” actually mean in terms of what is being optimized?
  2. Why is logistic regression discriminative but Naive Bayes generative, when both produce \(P(y\mid x)\) [the probability of label \(y\) given input \(x\)] for classification?
  3. How can generative models produce new inputs while discriminative models cannot?
  4. An LLM (using transformers) is trained to predict the next token given all previous tokens, which looks like supervised classification at each time step. So how is it generative?
  5. Since LLMs have become state of the art on many tasks, is the generative approach the only right way to do predictive modeling?

We will find answer for all these questions in a supervised binary classification setting (chosen for simplicity), using email spam detection as a running example, and then we will extrapolate it to understand how large language models are generative.

This post assumes basic probability (joint, conditional, Bayes’ rule) and some familiarity with ML (training, loss functions). Anything beyond that is recapped in the appendix

Notation#

How to read the math. Upright letters such as \(\text{x}\) denote a random variable (or, inside \(P(\text{y}\mid\text{x})\), the whole distribution). Italic letters such as \(x\) denote a specific value (an instance). So \(P(\text{y}\mid\text{x})\) is the conditional distribution as an object, and \(P(y\mid x)\) is the single number it assigns to a particular label \(y\) and input \(x\).

A bar means “given” (conditioning). A semicolon introduces parameters: \(P(y\mid x;\theta)\) reads “the probability of \(y\) given \(x\), under parameters \(\theta\)”. In sums and \(\operatorname{argmax}\), a letter such as \(c\) is a dummy variable that ranges over all its possible values.

Supervised learning setup for classification#

We will be doing binary classification and assume we are given a training set \(D\)

\[D=\{(x_1,y_1),\ (x_2,y_2),\ \ldots,\ (x_n,y_n)\}\]

  • \(n\) is the number of examples.
  • \(x_i\in\mathcal{X}\) is the input of the \(i\)-th example. \(\mathcal{X}\) is the input space (every possible input). We keep it abstract for now. It could be \(\mathbb{R}^d\) for numeric features, or sequences of words for text.
  • \(y_i\in\mathcal{Y}=\{0,1\}\) is the label of the \(i\)-th example. \(\mathcal{Y}\) is the label space (every possible answer).

Where does this data come from? Think of emails arriving in an inbox. Which emails show up is random, and whether a given email counts as spam is not a deterministic function of its text (two people may label the same email differently). We capture this by treating an input and its label as random variables \(\text{x}\) and \(\text{y}\), drawn from an unknown true data-generating distribution \(P^\ast(\text{x},\text{y})\). The training set is an i.i.d. sample from it (Appendix B):

\[(x_i,y_i)\ \overset{\text{i.i.d.}}{\sim}\ P^\ast(\text{x},\text{y}),\qquad i=1,\dots,n\]

Note the difference: \(D\) is a finite sample, and \(P^\ast\) is the unknown source it came from. Machine learning is, in the end, an attempt to learn something about \(P^\ast\) from \(D\).

\(P^\ast\) can be seen as underlying nature that generates spam or ham emails, eg for spam - scammers knowledge or purpose

For classification, the thing we want is the conditional distribution \(P^\ast(\text{y}\mid\text{x})\): given an input, how likely is each label? We cannot write it down, so we choose a family of candidate distributions \(P(\text{y}\mid\text{x};\theta)\) indexed by parameters \(\theta\), and look for the best \(\theta\).

Definition: parameterising a distribution. Choosing a formula for a probability mass function (discrete) or density (continuous) that contains adjustable numbers \(\theta\). Each setting of \(\theta\) gives one distribution, and training picks the setting. The nature of choosing \(\theta\) is based on how well it enables probability function to map \(x\) to \(y\), in ML these are the trainable weight parameters.

The one question: which distribution is the model learning?#

Suppose, hypothetically, we knew \(P^\ast(\text{x},\text{y})\). Then we could answer any probabilistic question about the data. The product rule (Appendix A) lets us factor the joint in two ways. For every input \(x\) and label \(y\):

\[P^\ast(x,y)=P^\ast(x\mid y)\,P^\ast(y)\tag{1}\]

\[P^\ast(x,y)=P^\ast(y\mid x)\,P^\ast(x)\tag{2}\]

Rearranging (2) gives the conditional we need for classification, \(P^\ast(y\mid x)=P^\ast(x,y)/P^\ast(x)\). Equating (1) and (2) gives Bayes’ rule:

\[P^\ast(y\mid x)=\frac{P^\ast(x\mid y)\,P^\ast(y)}{P^\ast(x)},\qquad P^\ast(x)=\sum_{c\in\mathcal{Y}}P^\ast(x\mid c)\,P^\ast(c)\tag{3}\]

(For continuous \(x\), replace the sum with an integral.)

So the joint contains the conditional, and more. That raises a natural question: instead of estimating only \(P^\ast(\text{y}\mid\text{x})\), can we estimate the joint from the data? Supervised learning approaches split by how they answer:

Definition

  • Discriminative learning models only the conditional \(P(\text{y}\mid\text{x};\theta)\). Inputs are taken as given and never modeled.
  • Generative learning models the joint, typically through (1): a class prior \(P(\text{y};\theta)\) times a class-conditional distribution \(P(\text{x}\mid\text{y};\theta)\). What matters is that the model includes a distribution over the inputs.

Both approaches learn a distribution, and which distribution it models determines what the model can do.

A discriminative model outputs a distribution over labels given an input. We can predict, or sample, a label for an input we already have. Nothing in the model describes what inputs look like, so it cannot produce new ones.

A generative model assigns a probability to every input–label pair. That gives us four abilities:

  1. Classify, through Bayes’ rule (3). The denominator \(P(x)\) is the same for every class, so to classify we only need to compare \(P(x\mid y)\,P(y)\) across classes.
  2. Sample new inputs: draw a label from the prior, then draw an input from that class’s distribution.
  3. Score inputs: the denominator of (3) tells us how typical an input is under the model.
  4. Handle missing data: if part of an input is missing, sum (or integrate) the joint over the missing part, \(P(x_{\text{observed}})=\sum_{x_{\text{missing}}}P(x_{\text{observed}},x_{\text{missing}})\). A model that never modeled inputs has no principled way to do this.

Intuition: boundary vs distribution. Both kinds of classifier end up with a decision boundary, the set of inputs where the two classes are equally probable. A discriminative model reaches it through \(P(y{=}1\mid x;\theta)=0.5\). A generative model reaches it where \(P(x\mid y{=}1)\,P(y{=}1)=P(x\mid y{=}0)\,P(y{=}0)\). The difference is not whether a boundary exists, but what the model had to learn to get one.

Why not always go generative, since it gives more? Because it also demands more. A discriminative model spends all of its capacity on \(P(\text{y}\mid\text{x})\). A generative model must also model the inputs, which is usually the harder part (we will see exactly how hard shortly). When labeled data is plentiful, discriminative classifiers typically reach lower classification error. When data is scarce, the structure a generative model assumes can act as a helpful bias and let it win. So “discriminative is better when you only care about the label” is a tendency, not a rule.

Aside: scope of this post. We focus on probabilistic models trained by maximum likelihood. Two caveats. First, not every discriminative model is probabilistic: an SVM learns a boundary directly, with no \(P(y\mid x)\). Second, some generative models (GANs, for example) learn to sample without ever writing down \(P(x)\), and their training objectives are not plain maximum likelihood. The “which distribution?” question is cleanest in the likelihood setting, so that is where we stay.

Key takeaway. Ask one question: which probability distribution is the model learning? Decision boundaries, sampling, and the ability to generate new inputs all follow from the answer.

What are we optimizing? KL divergence and maximum likelihood#

Once we have a family \(P(\text{y}\mid\text{x};\theta)\), how do we pick \(\theta\)? We want the model to be as close as possible to the truth. The KL divergence measures how far one distribution is from another (Appendix E). It is always \(\geq 0\), and it is \(0\) exactly when the two distributions are identical. For a conditional model we average it over inputs:

\[\theta^\star=\underset{\theta}{\operatorname{argmin}}\ \ \mathbb{E}_{x\sim P^\ast(\text{x})}\Big[\mathrm{KL}\big(P^\ast(\text{y}\mid x)\ \Vert\ P(\text{y}\mid x;\theta)\big)\Big]\tag{4}\]

This is an ideal optimisation, we want the model’s conditional distribution to be as close as possible to the true conditional distribution. However, we cannot compute (4), because it needs \(P^\ast\) (which is always unknown). But look at what it contains. Expanding the KL divergence splits it into two terms:

\[\mathbb{E}_{x}\Big[\mathrm{KL}\big(P^\ast(\text{y}\mid x)\ \Vert\ P(\text{y}\mid x;\theta)\big)\Big]=\underbrace{\mathbb{E}_{(x,y)\sim P^\ast}\big[\log P^\ast(y\mid x)\big]}_{\text{does not depend on }\theta}\ -\ \mathbb{E}_{(x,y)\sim P^\ast}\big[\log P(y\mid x;\theta)\big]\]

The first term is a constant as far as \(\theta\) is concerned. So minimizing the KL divergence is the same as maximizing the expected log-probability the model assigns to the true data. We cannot take that expectation under \(P^\ast\), but we do have i.i.d. samples from \(P^\ast\), and an average over samples approximates an expectation (the law of large numbers):

\[\theta^\star=\underset{\theta}{\operatorname{argmax}}\ \mathbb{E}_{(x,y)\sim P^\ast}\big[\log P(y\mid x;\theta)\big]\ \approx\ \underbrace{\underset{\theta}{\operatorname{argmax}}\ \frac{1}{n}\sum_{i=1}^{n}\log P(y_i\mid x_i;\theta)}_{\hat\theta\ :\ \text{the maximum likelihood estimate}}\tag{5}\]

The right-hand side only involves our training data, so we can compute it. This is maximum likelihood estimation (MLE) (Appendix D).

NOTE - Maximum likelihood estimation approximating KL divergence holds only if the samples are drawn i.i.d from \(P^\ast\), if sampling is biased or very less in number the approximation may not be generalisable and model overfits to the sampled data.

Key takeaway. “Learning a distribution” means choosing \(\theta\) so the model assigns high probability to the data we observed. That is maximum likelihood, and it approximately minimizes the KL divergence to the true distribution. The recipe is the same whichever distribution we model (for the joint, replace \(P(y\mid x;\theta)\) with \(P(x,y;\theta)\)). Only the quantity being maximized changes:

  • Discriminative: \(\prod_{i=1}^{n} P(y_i\mid x_i;\theta)\)
  • Generative: \(\prod_{i=1}^{n} P(x_i,y_i;\theta)\)

Now let’s make this concrete with a running example.

Running example: representing an email#

Let us classify emails as spam (\(y=1\)) or ham (\(y=0\)) to understand the workings of both modelling approaches. For a fair comparison, both approaches should see exactly the same information, so we use the bag-of-words representation for both:

  • A vocabulary \(V\) of \(\lvert V\rvert\) distinct words we track, indexed \(1,\dots,\lvert V\rvert\).
  • As a sequence, email \(i\) is \(x_i=(x_{i,1},x_{i,2},\dots,x_{i,m_i})\), where \(m_i\) is the number of words and each \(x_{i,j}\in\{1,\dots,\lvert V\rvert\}\) is the index of the word at position \(j\).
  • As a count vector, email \(i\) is \(t_i=(t_{i,1},\dots,t_{i,\lvert V\rvert})\), where \(t_{i,k}\) is how many times word \(k\) appears in the email, so \(\sum_k t_{i,k}=m_i\). Counts forget word order. We also write \(t(x)\) for the count vector of an email \(x\).

Example. Take a toy vocabulary \(V=(\text{free},\ \text{prize},\ \text{click},\ \text{meeting},\ \text{report},\ \text{thanks})\), indexed \(1,\dots,6\). The email “free prize free” is the sequence \(x=(1,2,1)\) with \(m=3\), and its count vector is \(t(x)=(2,1,0,0,0,0)\).

The discriminative model will take the count vector \(t(x)\) as its input, because logistic regression needs a fixed-length numeric vector. The generative model will model the word sequence directly, and we will see that its likelihood depends on an email only through its counts. So both approaches use the same information: which words appear, and how often.

Discriminative approach: logistic regression#

In the discriminative approach we model only \(P(\text{y}\mid\text{x})\).

The model. Given an email \(x\), compute a score from its word counts, \(w^\top t(x)+b\). There is one weight per vocabulary word (\(w\in\mathbb{R}^{\lvert V\rvert}\)), so spammy words get positive weights and hammy words get negative ones. Then squash the score into a probability with the sigmoid \(\sigma(z)=1/(1+e^{-z})\):

\[f_\theta(x)=\sigma\big(w^\top t(x)+b\big)=P(y{=}1\mid x;\theta),\qquad \theta=(w,b)\tag{6}\]

Note that the output is a probability, not a label. \(f_\theta(x)\) is the probability that email \(x\) is spam, and \(1-f_\theta(x)\) is the probability that it is ham.

The distribution. For each training email, the label follows a Bernoulli distribution (Appendix C) whose parameter is \(p_i=f_\theta(x_i)\):

\[P(y_i\mid x_i;\theta)=p_i^{\,y_i}\,(1-p_i)^{1-y_i}\]

(If \(y_i=1\) this equals \(p_i\), and if \(y_i=0\) it equals \(1-p_i\).) Each email has its own \(p_i\). That is why we use a Bernoulli per example rather than one binomial over the whole dataset, since a binomial counts successes over trials that share a single probability.

The likelihood. Since the examples are i.i.d., the probability of all the observed labels is the product of the per-example probabilities:

\[L(\theta)=\prod_{i=1}^{n}P(y_i\mid x_i;\theta)=\prod_{i=1}^{n}f_\theta(x_i)^{y_i}\,\big(1-f_\theta(x_i)\big)^{1-y_i}\tag{7}\]

\(L(\theta)\) is the probability the model assigns to the labels we actually observed, viewed as a function of \(\theta\) (Appendix D). Maximum likelihood picks the \(\theta\) for which those labels are most probable.

Products of many numbers below \(1\) underflow numerically and are awkward to differentiate, so we take the log. The log is increasing, so it does not change which \(\theta\) maximizes the function:

\[\ell(\theta)=\log L(\theta)=\sum_{i=1}^{n}\Big[\,y_i\log f_\theta(x_i)+(1-y_i)\log\big(1-f_\theta(x_i)\big)\Big],\qquad \hat\theta=\underset{\theta}{\operatorname{argmax}}\ \ell(\theta)\tag{8}\]

If you look closely at \(\ell(\theta)\), it is the negative of the binary cross-entropy loss that we usually minimize when training classifiers (Appendix E). So maximizing the log-likelihood is the same as minimizing cross-entropy. There is no closed-form solution, so \(\theta\) is found iteratively with gradient-based optimization.

What can this model do? It gives us the probability of spam for any email, and we can sample a label \(y\sim\text{Bernoulli}(f_\theta(x))\) for an email we already have. But nothing in the model describes what emails look like. There is no distribution over emails to sample from. Since only the conditional distribution is modeled, this is a discriminative model.

Key takeaway. We are interested in finding \(P(y_i\mid x_i;\theta)\), since \(y\) heavily depends on \(x\), we parameterised the distribution with \(\theta\) (representing logistic regression) and found the optimal \(\hat\theta\) by maximizing the log-likelihood. Resultant is an accurate conditional distribution \(P(y_i\mid x_i;\hat\theta)\), which outputs distribution only over labels.

Generative approach: Naive Bayes#

In the generative approach we model the joint distribution through equation (1):

\[P(x,y;\theta)=P(x\mid y;\theta)\,P(y;\theta)\tag{9}\]

So there are two pieces to parameterise: the class prior \(P(\text{y};\theta)\) (how often is an email spam?) and the class-conditional distribution \(P(\text{x}\mid\text{y};\theta)\) (what does a spam email look like, and what does a ham email look like?).

The MLE logic is the same as before: i.i.d. data, maximize the likelihood. Only the quantity inside the product changes, from \(\prod_i P(y_i\mid x_i;\theta)\) to \(\prod_i P(x_i,y_i;\theta)\).

Intuition: what does the joint objective add? Maximizing the joint likelihood minimizes the joint KL divergence, which splits into two parts (the chain rule for KL):

\[\mathrm{KL}\big(P^\ast(\text{x},\text{y})\,\Vert\,P(\text{x},\text{y};\theta)\big)=\mathrm{KL}\big(P^\ast(\text{x})\,\Vert\,P(\text{x};\theta)\big)+\mathbb{E}_{x\sim P^\ast(\text{x})}\Big[\mathrm{KL}\big(P^\ast(\text{y}\mid x)\,\Vert\,P(\text{y}\mid x;\theta)\big)\Big]\]

Here \(P(\text{x};\theta)\) and \(P(\text{y}\mid x;\theta)\) are the marginal and conditional implied by the joint model. The second term is exactly the discriminative objective (4). The first term is extra: a generative model is also rewarded for modeling the inputs. With a perfectly flexible model both terms can reach zero together. With an imperfect model, such as Naive Bayes below, capacity spent on \(P(\text{x})\) can cost accuracy on \(P(\text{y}\mid\text{x})\). This is the precise version of “discriminative models don’t spend capacity on inputs”.

But how does a joint model classify? Use Bayes’ rule (3). Given a new email \(x\), the denominator \(P(x)\) is the same for both classes, so we only compare \(P(x\mid y)\,P(y)\) across the two classes.

For spam classification, the simplest generative solution is Naive Bayes. The rest of this section builds it step by step: why \(P(\text{x}\mid\text{y})\) is hard to model, the assumptions that tame it, the full MLE derivation, and finally what the learned model can do, including sampling new emails, which makes it generative.

The problem: modeling \(P(\text{x}\mid\text{y})\) directly is intractable#

To use equation (1) we need \(P(\text{x}\mid \text{y})\): the probability of an entire email given its class. An email of \(m\) words is a sequence \(x=(x_1,\dots,x_m)\), and there are \(\lvert V\rvert^m\) possible sequences. A general model with probability as parameter, needs a separate parameter for each of them. (A distribution over \(N\) outcomes has \(N-1\) free numbers, because the probabilities must sum to \(1\).)

With a modest vocabulary of \(50{,}000\) words and a \(200\)-word email, that is \(50{,}000^{200}\approx 10^{940}\) outcomes. On top of that, emails have different lengths, so we would need a separate distribution for each length.

This is the cost the discriminative approach never pays, because it does not model the inputs at all. A generative model cannot skip it, so it has to simplify \(P(\text{x}\mid\text{y})\).

The simplification: Naive Bayes assumptions#

1. Conditional independence (the “naive” assumption). Given the class, the words of an email are independent of each other:

\[P(x\mid y)=\prod_{j=1}^{m}P(x_j\mid y)\tag{10}\]

The \(10^{940}\)-outcome distribution collapses into \(m\) small distributions, one over words at each position.

2. Position independence. Every position uses the same word distribution for a given class:

\[P(x_j=k\mid y=c)=\phi_{k\mid c}\qquad\text{for every position }j\tag{11}\]

The model does not care where a word appears, only which words appear and how often. An email becomes a bag of words.

Example. The probability of seeing “free” in a spam email is \(\phi_{\text{free}\mid\text{spam}}\) whether it is the 1st word or the 50th. Reordering an email does not change its probability, because the same factors are simply multiplied in a different order:

\[P(\text{"free prize now"}\mid\text{spam})=\phi_{\text{free}\mid\text{spam}}\,\phi_{\text{prize}\mid\text{spam}}\,\phi_{\text{now}\mid\text{spam}}=P(\text{"now free prize"}\mid\text{spam})\]

This assumption is separate from conditional independence, and it is needed for two practical reasons. First, emails have different lengths, so “position 3” does not mean the same thing in a 10-word email and a 200-word one, and positions beyond the longest training email would have no data at all. Second, it lets every word occurrence in the training set, at any position, inform the same \(\phi_{k\mid c}\).

Here is how much each assumption shrinks the number of parameters:

Model of \(P(\text{x}\mid\text{y})\)Parameters (two classes plus the prior)
Full joint (one probability per possible email)\(2\,(\lvert V\rvert^{m}-1)+1\)
Conditional independence only (a separate distribution at each of the \(m\) positions)\(2\,m\,(\lvert V\rvert-1)+1\)
Conditional independence + position independence (one distribution per class)\(2\,(\lvert V\rvert-1)+1\)

The parameters. Under the two assumptions, the whole model has just these parameters:

  • \(\pi=P(y{=}1)\), the probability that a random email is spam.
  • \(\phi_{k\mid c}=P(\text{word }k\mid y{=}c)\), the probability that a word in a class-\(c\) email is word \(k\), with \(\sum_{k=1}^{\lvert V\rvert}\phi_{k\mid c}=1\) for each class \(c\).

\[\theta=\{\pi,\ \phi_{\cdot\mid 0},\ \phi_{\cdot\mid 1}\}\]

A consequence: the multinomial. This is not a third assumption, it follows from the first two. Each word is now an independent draw from a categorical distribution over \(V\) (Appendix C). If we summarise an email of \(m\) words by its count vector \(t=(t_1,\dots,t_{\lvert V\rvert})\), that vector follows a multinomial distribution:

\[P(t\mid y=c)=\frac{m!}{t_1!\cdots t_{\lvert V\rvert}!}\ \prod_{k=1}^{\lvert V\rvert}\phi_{k\mid c}^{\,t_k}\tag{12}\]

The coefficient \(\frac{m!}{\prod_k t_k!}\) counts the orderings that produce the same bag of words. It does not depend on \(\phi\), so it drops out when we maximize over \(\phi\). Modeling the sequence or the count vector gives the same MLE. This is why the model only ever needs the counts \(t(x)\), which is exactly what we fed logistic regression.

What this means for spam classification:

  • Words are unrelated given the class. Given that an email is spam, seeing “free” tells us nothing about whether “prize” will also appear. In reality these words clearly co-occur, so the assumption is wrong.
  • Order and negation are lost. “This is not a scam” and “this is a scam” have almost the same bag of words.
  • It still works for classification. We only need the ranking of \(P(\text{spam}\mid x)\) against \(P(\text{ham}\mid x)\), and that is often right even when the independence assumption is wrong. The probabilities themselves tend to be overconfident, because correlated words get counted as independent evidence.

Deriving the MLE#

We have \(n\) labeled emails \(\{(x_i,y_i)\}_{i=1}^n\). Define the following counts (they turn out to be all the model needs from the data):

  • \(N_c=\sum_{i=1}^{n}\mathbb{1}\{y_i=c\}\), the number of class-\(c\) emails (so \(N_0+N_1=n\)).
  • \(N_{k,c}=\sum_{i=1}^{n}\mathbb{1}\{y_i=c\}\ t_{i,k}\), the total number of times word \(k\) appears across all class-\(c\) emails.
  • \(M_c=\sum_{k}N_{k,c}\), the total number of words across all class-\(c\) emails.

Step 1: Joint likelihood. Assuming i.i.d. emails, and applying equation (9) plus the two assumptions (we treat each email’s length \(m_i\) as given):

\[L(\theta)=\prod_{i=1}^{n}P(x_i,y_i;\theta)=\prod_{i=1}^{n}P(y_i;\pi)\ \prod_{j=1}^{m_i}P(x_{i,j}\mid y_i;\phi)\]

The label is Bernoulli, \(P(y_i;\pi)=\pi^{\,y_i}(1-\pi)^{1-y_i}\), and each word probability is \(P(x_{i,j}\mid y_i;\phi)=\phi_{x_{i,j}\mid y_i}\).

Step 2: Log-likelihood.

\[\ell(\theta)=\sum_{i=1}^{n}\Big[\,y_i\log\pi+(1-y_i)\log(1-\pi)\Big]+\sum_{i=1}^{n}\sum_{j=1}^{m_i}\log\phi_{x_{i,j}\mid y_i}\]

Step 3: Regroup by class and word. The double sum visits every word occurrence once. Grouping equal terms together, word \(k\) in class \(c\) shows up exactly \(N_{k,c}\) times, and \(\sum_i y_i=N_1\), \(\sum_i(1-y_i)=N_0\):

\[\ell(\theta)=\underbrace{N_1\log\pi+N_0\log(1-\pi)}_{\text{depends only on }\pi}\ +\ \underbrace{\sum_{c\in\{0,1\}}\sum_{k=1}^{\lvert V\rvert}N_{k,c}\log\phi_{k\mid c}}_{\text{depends only on the word distributions}}\tag{13}\]

This is the key structural observation: the objective splits into independent problems, one for the class prior and one for each class’s word distribution. We can maximize each separately.

Step 4: Maximize the class prior. Differentiate with respect to \(\pi\) and set to zero:

\[\frac{\partial\ell}{\partial\pi}=\frac{N_1}{\pi}-\frac{N_0}{1-\pi}=0\quad\Longrightarrow\quad\pi=\frac{N_1}{N_0+N_1}=\frac{N_1}{n}\]

The estimated prior is simply the fraction of training emails that are spam.

Step 5: Maximize the word distributions. For each class \(c\) we maximize \(\sum_k N_{k,c}\log\phi_{k\mid c}\) subject to \(\sum_k\phi_{k\mid c}=1\). This is a constrained problem, so we use a Lagrange multiplier \(\lambda_c\) (Appendix F):

\[\mathcal{J}(\phi_{\cdot\mid c},\lambda_c)=\sum_{k=1}^{\lvert V\rvert}N_{k,c}\log\phi_{k\mid c}+\lambda_c\Big(1-\sum_{k=1}^{\lvert V\rvert}\phi_{k\mid c}\Big)\]

Differentiate with respect to \(\phi_{k\mid c}\) and set to zero:

\[\frac{N_{k,c}}{\phi_{k\mid c}}-\lambda_c=0\quad\Longrightarrow\quad\phi_{k\mid c}=\frac{N_{k,c}}{\lambda_c}\]

Now use the constraint to find \(\lambda_c\):

\[\sum_k\phi_{k\mid c}=\frac{\sum_k N_{k,c}}{\lambda_c}=1\quad\Longrightarrow\quad\lambda_c=\sum_k N_{k,c}=M_c\]

Substituting back:

\[\boxed{\ \phi_{k\mid c}=\frac{N_{k,c}}{\sum_{k'}N_{k',c}}=\frac{\text{count of word }k\text{ in class-}c\text{ emails}}{\text{total words in class-}c\text{ emails}}\ }\tag{14}\]

The MLE has a simple interpretation: \(\phi_{k\mid c}\) is the fraction of all words in class-\(c\) emails that are word \(k\). Training Naive Bayes is just counting.

Step 6 (optional): check that it is a maximum

Each \(\log\phi_{k\mid c}\) is concave, and a non-negative weighted sum of concave functions is concave (the weights \(N_{k,c}\) are non-negative). The prior’s objective \(N_1\log\pi+N_0\log(1-\pi)\) is concave for the same reason. The constraint is linear, so each stationary point we found is the global maximum.

The solution is also automatically non-negative, so the constraint \(\phi_{k\mid c}\geq 0\) never becomes active. One edge case: if a word never appears in a class, then \(N_{k,c}=0\) and the solution is \(\phi_{k\mid c}=0\) (using the convention \(0\cdot\log 0=0\)). This is the zero-count problem we deal with at the end of the section.

What the learned model gives us#

A toy model. To make the next two ideas concrete, take the six-word vocabulary from earlier and suppose training produced a prior \(\pi=0.4\) and the following word distributions:

Word\(\phi_{k\mid\text{spam}}\)\(\phi_{k\mid\text{ham}}\)
free0.300.02
prize0.250.01
click0.250.07
meeting0.020.35
report0.030.30
thanks0.150.25

(Each column sums to \(1\).)

Classification. Given a new email with word counts \(t=t(x)\), we compare the two classes using Bayes’ rule (3), dropping \(P(x)\) because it is the same for both:

\[\hat y=\underset{c\in\mathcal{Y}}{\operatorname{argmax}}\ \Big[\log P(c)+\sum_{k=1}^{\lvert V\rvert}t_k\log\phi_{k\mid c}\Big],\qquad P(1)=\pi,\ \ P(0)=1-\pi\tag{15}\]

We work in log space because multiplying hundreds of small probabilities underflows to zero. For our tiny examples we can multiply directly. Take the email “free prize”:

  • Spam score: \(\pi\cdot\phi_{\text{free}\mid\text{spam}}\cdot\phi_{\text{prize}\mid\text{spam}}=0.4\times 0.30\times 0.25=0.030\)
  • Ham score: \((1-\pi)\cdot\phi_{\text{free}\mid\text{ham}}\cdot\phi_{\text{prize}\mid\text{ham}}=0.6\times 0.02\times 0.01=0.00012\)

The two scores add up to \(P(x)\), the denominator in (3), so

\[P(\text{spam}\mid x)=\frac{0.030}{0.030+0.00012}\approx 0.996\]

Now take “meeting report thanks”. The spam score is \(0.4\times 0.02\times 0.03\times 0.15=0.000036\), the ham score is \(0.6\times 0.35\times 0.30\times 0.25=0.01575\), and \(P(\text{spam}\mid x)\approx 0.0023\). The model is very confident in both cases.

Sampling: what a generated email looks like. Because we learned \(P(x\mid y)\) and \(P(y)\), we can also run the model forwards. First draw the label, then draw the words given the label (this is called ancestral sampling):

  1. Draw a label \(y\sim\text{Bernoulli}(\pi)\).
  2. Choose a length \(m\). The multinomial model conditions on the length and does not model it, so we supply it ourselves (for example, from the training length distribution).
  3. For each of the \(m\) positions, draw a word independently, \(x_j\sim\text{Categorical}(\phi_{\cdot\mid y})\).

Suppose step 1 gives \(y=\text{spam}\) and we choose \(m=8\). Eight independent draws from the spam column might give:

prize  free  click  free  thanks  prize  free  click

As a bag of words, in the vocabulary order (free, prize, click, meeting, report, thanks), this is the count vector

\[(3,\ 2,\ 2,\ 0,\ 0,\ 1)\]

Notice that this is not a readable email. The order above is meaningless, because each position was drawn independently, so any shuffle of those eight words is exactly as likely. The model generates bags of words that have the right word frequencies for the class. A ham sample would look completely different, for example meeting report thanks meeting report meeting click thanks, which is the count vector \((0,0,1,3,2,2)\).

This is how a generative model produces new inputs, which answers question 4. The samples are crude, but the model really does assign a probability to every email, and the logistic regression model above has nothing comparable.

Aside: zero counts (Laplace smoothing). If a word never appears in spam emails in the training set, then \(N_{k,\text{spam}}=0\) and \(\phi_{k\mid\text{spam}}=0\). Any new email containing that word would then get \(P(x\mid\text{spam})=0\), regardless of every other word. The standard fix is to add \(1\) to every count:

\[\phi_{k\mid c}=\frac{N_{k,c}+1}{M_c+\lvert V\rvert}\tag{16}\]

This is no longer the pure MLE. It is the MAP estimate under a symmetric Dirichlet prior with parameter \(\alpha=2\), which acts like one extra “pseudo-count” per word (Appendix G).

Now we have an idea on how discriminative and generative modeling operates, its time to address the most trending generative model the LLMs. As we saw Naive Bayes makes the generative problem tractable by assuming words are independent given the class, which results in bag-of-words, but as we all know LLMs clearly do not have this limitation, they are aware of the complex long-term sequence of words (even more than 100k words) which makes them one of the most powerful generative models. Lets understand in detail how this is done in next section.

Language modeling#

Naive Bayes made generative modeling tractable by assuming words are independent given the class, which reduced every email to a bag of words. Large language models do not accept that limitation: they condition on the entire preceding text, sometimes hundreds of thousands of tokens of it. This section builds up how that is possible, in the same spirit as the rest of the post: which distribution is being learned, and how is it parameterised and trained? We will go through:

  • what a language model is, and why it is generative,
  • why the most direct way of building one cannot work,
  • how the autoregressive factorization solves the problem, and why it is the standard choice,
  • the maximum likelihood derivation (and the answer to the “next-token classification” puzzle from the introduction),
  • how the parameterisation evolved from simple counting to Transformers, and how that lets models use very long contexts.

What is a language model?#

A language model is a probability distribution over sequences of tokens.

We reuse the setup from the running example. There is a vocabulary \(V\) of \(\lvert V\rvert\) tokens, and a text is a sequence \(x=(x_1,x_2,\dots,x_m)\) where each \(x_j\in\{1,\dots,\lvert V\rvert\}\) is the index of the token at position \(j\). (In practice tokens are often pieces of words rather than whole words. We will use “token” and “word” interchangeably.) The only differences from the email setting are that there is no label, and that we no longer throw away word order.

As before, there is an unknown true distribution \(P^\ast(\text{x})\), now over texts. It gives high probability to sequences like “The cat sat on the mat” and very low probability to “Mat the on sat cat the” or to random strings of tokens. A language model is a parameterised distribution \(P(\text{x};\theta)\) that tries to approximate it. Our training set is simply a collection of texts, \(D=\{x_1,\dots,x_n\}\), where text \(x_i=(x_{i,1},\dots,x_{i,m_i})\), assumed i.i.d. from \(P^\ast\).

Texts have different lengths, so the model also has to say when a text ends. We handle this with a special end-of-sequence token (EOS) appended to every text. The model treats “stop here” as just another token it can predict. This fixes a gap we noticed in the Naive Bayes sampler, where the length \(m\) was something we had to supply ourselves.

Connection to Naive Bayes. Naive Bayes already contains a language model. For each class, \(P(x\mid y)=\prod_j\phi_{x_j\mid y}\) is a distribution over word sequences, one that ignores order and context. A language model is the same kind of object, with a far more expressive way of assigning probabilities.

How is it generative?#

Apply the question the whole post is built around: which distribution is the model learning? A language model learns \(P(\text{x})\), a distribution over the inputs themselves. There is no separate label to condition on, because the text is the data. By the definition we used earlier, a model that includes a distribution over inputs is generative.

Here is how it stacks up against the four abilities of a generative model:

AbilityLanguage model
Sample new inputsYes: generate new text.
Score inputsYes: \(P(x;\theta)\) says how likely a text is under the model.
Classify via Bayes’ ruleNot directly, since there is no label. It works if we train one LM per class, \(P(x\mid y)P(y)\), which is Naive Bayes with a much better \(P(x\mid y)\).
Handle missing dataPartially: continuing a text from a given beginning is natural. Filling a gap in the middle means summing over all possible fillings.

There is one puzzle to resolve. An LLM is trained to predict the next token given the previous ones, which looks like an ordinary classification problem at every step. How can that be a generative model of whole texts? We will answer this precisely once we have the factorization and the likelihood in hand.

Why a straightforward language model is impossible#

The most direct approach is the one we first considered for Naive Bayes: treat \(P(\text{x})\) as one giant categorical distribution over all possible texts, with one probability per text.

A text of \(m\) tokens has \(\lvert V\rvert^m\) possibilities, and a distribution over \(N\) outcomes has \(N-1\) free numbers. With the same numbers as before, \(\lvert V\rvert=50{,}000\) and a \(200\)-token text, that is about \(10^{940}\) probabilities. Real contexts are far longer: at \(1{,}000\) tokens it is about \(10^{4699}\). This direct approach fails for three separate reasons:

  1. Size. We cannot store, estimate, or even index that many numbers. No neural network could have an output layer with one unit per possible text.
  2. No generalization. Maximum likelihood for a table is just counting. Maximizing \(\sum_x N_x\log P(x)\) subject to \(\sum_x P(x)=1\) (the same Lagrange argument as in the Naive Bayes derivation) gives \(\hat P(x)=N_x/n\), where \(N_x\) is how many times text \(x\) appears in the training set. Every text that is not in the training set gets probability \(0\), including perfectly valid sentences nobody happened to write down. Even all text ever written covers a vanishing fraction of \(\lvert V\rvert^m\). The model would memorize rather than learn. (Laplace smoothing does not help here. It would just give every unseen text the same tiny probability, which carries no information.)
  3. Variable length. Texts have different lengths, so we would need a separate table for each length, or some other way to handle it.

Naive Bayes avoided this by assuming that words are independent given the class and that position does not matter (equations 10 and 11), at the cost of discarding order and context. A language model has to produce coherent text, so we need a way to cut down the problem without discarding dependencies between tokens.

The autoregressive solution#

The chain rule of probability (Appendix A) gives exactly such a way. For any distribution, with no assumptions at all, a text can be generated one token at a time. Write \(x_{<j}=(x_1,\dots,x_{j-1})\) for everything before position \(j\). For the true distribution,

\[P^\ast(x_1,\dots,x_m)=\prod_{j=1}^{m}P^\ast(x_j\mid x_{<j})\tag{17}\]

where the first factor \(P^\ast(x_1\mid x_{<1})\) is the distribution of the first token given an empty context (in practice, a special start token). Our model uses the same factorization, with each factor parameterised:

\[P(x_1,\dots,x_m;\theta)=\prod_{j=1}^{m}P(x_j\mid x_{<j};\theta)\tag{18}\]

For example, \(P(\text{The cat sat})=P(\text{The})\,P(\text{cat}\mid\text{The})\,P(\text{sat}\mid\text{The cat})\).

Three things are worth noticing.

The factorization is exact. Equation (17) is not an approximation. The only approximation is in how we model each factor \(P(x_j\mid x_{<j})\).

Each factor is a small problem. Instead of one distribution over \(\lvert V\rvert^m\) texts, we have a sequence of distributions, each over only \(\lvert V\rvert\) outcomes: what is the next token, given everything so far? The EOS token is one of those outcomes, so deciding when to stop is part of the model.

Naive Bayes is this factorization with the history deleted. Compare equation (10) with (17). Naive Bayes replaces \(P(x_j\mid x_{<j},y)\) with \(P(x_j\mid y)\): it deletes the history (conditional independence) and shares the same distribution across positions (position independence). A language model keeps the history. The whole difficulty now moves into one question: how do we represent \(P(x_j\mid x_{<j};\theta)\) for histories of any length? There are exponentially many possible prefixes, so we cannot keep a separate table row for each. We need a single function with shared parameters that maps any prefix to a distribution over the vocabulary.

Sampling. The ancestral sampling we used for Naive Bayes extends directly. Draw the first token from \(P(\cdot\,;\theta)\). Then feed it back in, draw the second from \(P(\cdot\mid x_1;\theta)\), then the third from \(P(\cdot\mid x_1,x_2;\theta)\), and so on until EOS is drawn. Because the joint is the product of the conditionals, the finished text is a sample from \(P(\text{x};\theta)\) (sampled outputs are proper texts unlike Naive Bayes).

Prompts. When we chat with a model, we want \(P(\text{response}\mid\text{prompt})\). With a prompt \(C=(c_1,\dots,c_r)\) and a response \(Y=(y_1,\dots,y_s)\), it is the same factorization with the prompt in front:

\[P(Y\mid C;\theta)=\prod_{j=1}^{s}P(y_j\mid C,y_{<j};\theta)\tag{19}\]

Why this is the standard approach. Several things make autoregressive modeling the default choice:

  • Exact, tractable likelihood. We can compute \(P(x;\theta)\) exactly, so the maximum likelihood recipe from earlier applies directly, with no intractable sums or normalizing constants.
  • Simple sampling. Generation is one token at a time, as above.
  • Efficient training. A single text of \(m\) tokens provides \(m\) next-token training examples, and all of them can be computed in a single pass through the model.
  • It scales. The same recipe works from small models up to the largest ones.

The form of each conditional#

To train anything we need a concrete form for \(P(x_j\mid x_{<j};\theta)\). Suppose, for now, that some function \(g_\theta\) turns the prefix into a vector \(h_j\) that summarizes it (we will see how \(g_\theta\) evolved in the next subsections):

\[h_j=g_\theta(x_{<j})\]

From \(h_j\) we compute one score (logit) per vocabulary token, \(z_{j,k}=w_k^\top h_j+b_k\), and turn the scores into probabilities with the softmax:

\[P(x_j=k\mid x_{<j};\theta)=\frac{\exp(z_{j,k})}{\sum_{k'=1}^{\lvert V\rvert}\exp(z_{j,k'})}\tag{20}\]

This is a categorical distribution over the vocabulary (Appendix C). For a prefix “The cat”, it might look like this (illustrative numbers):

Next tokenProbability
sat0.70
ran0.08
is0.05
ate0.03
all other tokens combined0.14

At every step the model answers one question: what is the probability distribution of the next token given everything so far?

Connection to logistic regression. The softmax is the multi-class generalization of the sigmoid. With only two classes, \(\frac{e^{z_1}}{e^{z_0}+e^{z_1}}=\sigma(z_1-z_0)\), so equation (6) is the two-class special case (Appendix H). The next-token head is therefore multinomial logistic regression, with one difference: logistic regression above used hand-built features (the word counts \(t(x)\)), while here the features \(h_j\) are learned.

Deriving the MLE#

The derivation follows the Naive Bayes one step by step. We have \(n\) texts \(D=\{x_1,\dots,x_n\}\), where \(x_i=(x_{i,1},\dots,x_{i,m_i})\).

Step 1: Likelihood. The texts are i.i.d., so the likelihood is the product of the probabilities of the texts. Applying the factorization (18) to each text:

\[L(\theta)=\prod_{i=1}^{n}P(x_i;\theta)=\prod_{i=1}^{n}\prod_{j=1}^{m_i}P(x_{i,j}\mid x_{i,<j};\theta)\tag{21}\]

Step 2: Log-likelihood. The log turns the double product into a double sum:

\[\ell(\theta)=\sum_{i=1}^{n}\sum_{j=1}^{m_i}\log P(x_{i,j}\mid x_{i,<j};\theta),\qquad \hat\theta=\underset{\theta}{\operatorname{argmax}}\ \ell(\theta)\tag{22}\]

Step 3: Recognize the loss. Each term is the log-probability the model assigns to the token that actually came next. Write the true next token as a one-hot vector, so that \(\mathbb{1}\{k=x_{i,j}\}\) is \(1\) for the correct token and \(0\) otherwise. Then

\[-\log P(x_{i,j}\mid x_{i,<j};\theta)=-\sum_{k=1}^{\lvert V\rvert}\mathbb{1}\{k=x_{i,j}\}\,\log P(x_{i,j}=k\mid x_{i,<j};\theta)\]

This is the (categorical) cross-entropy between the one-hot true token and the model’s predicted distribution (Appendix E). Maximizing the log-likelihood is therefore the same as minimizing the next-token cross-entropy loss, averaged over all \(N=\sum_i m_i\) token positions:

\[\hat\theta=\underset{\theta}{\operatorname{argmin}}\ -\frac{1}{N}\sum_{i=1}^{n}\sum_{j=1}^{m_i}\log P(x_{i,j}\mid x_{i,<j};\theta)\tag{23}\]

This is exactly equation (8), with the Bernoulli replaced by a categorical distribution. As with logistic regression, there is no closed-form solution, so \(\theta\) is found by gradient-based optimization.

Contrast with the Naive Bayes MLE. Suppose instead we gave every possible prefix \(u\) its own categorical distribution (a table). The same Lagrange argument as in equation (14) would give relative frequencies, \(P(x_j=k\mid u)=N_{u,k}/\sum_{k'}N_{u,k'}\), where \(N_{u,k}\) counts how often token \(k\) followed prefix \(u\) in the data. Naive Bayes is the special case where the prefix is ignored, so there is a single context and plenty of data per count. With the full history, almost every prefix appears at most once, and the counts say nothing about prefixes we have not seen. The softmax model (20) avoids this because the parameters inside \(g_\theta\) are shared across all prefixes.

Example. Take the text “The cat sat” (ignoring EOS for brevity) and suppose the model assigns \(P(\text{The})=0.01\), \(P(\text{cat}\mid\text{The})=0.08\), and \(P(\text{sat}\mid\text{The cat})=0.7\). Then

\[P(\text{The cat sat})=0.01\times0.08\times0.7=0.00056\]

and the negative log-likelihood is \(-\ln 0.00056\approx 7.49\), or about \(2.50\) per token. Training adjusts \(\theta\) to push this number down across the whole corpus.

Perplexity. The standard way to report how well a language model fits a text is perplexity, the exponential of the average per-token loss:

\[\text{PPL}=\exp\Big(-\frac{1}{N}\sum_{i,j}\log P(x_{i,j}\mid x_{i,<j};\theta)\Big)\]

For the example above, \(\exp(2.50)\approx 12.1\): on average, the model is as uncertain as if it were choosing uniformly among about 12 tokens at each step. Lower is better.

Key takeaway: classifiers inside, generative outside. Each factor of a language model is a classifier, trained by maximum likelihood exactly like logistic regression, with \(\lvert V\rvert\) classes. But the objective we maximize is the likelihood of the whole text, \(\prod_i P(x_i;\theta)\), which is a joint over inputs. The only thing that changed relative to the earlier recipe is the quantity inside the likelihood:

  • Discriminative: \(\prod_{i} P(y_i\mid x_i;\theta)\)
  • Generative (Naive Bayes): \(\prod_{i} P(x_i,y_i;\theta)\)
  • Language model: \(\prod_{i} P(x_i;\theta)=\prod_{i}\prod_{j}P(x_{i,j}\mid x_{i,<j};\theta)\)

What makes it generative is that every token of the text is a label somewhere. A token is the label at its own position and then becomes part of the input at later positions, so nothing about the text is left unmodeled. A discriminative classifier takes its inputs as given and never models them. A language model models its own inputs, one token at a time. And because the labels are simply the next tokens in the data, no human labeling is needed.

Training learns the distribution, and generation samples from it. They are two sides of the same model, not two separate things.

Parameterization: from n-gram tables to Transformers#

Everything so far, including the factorization, the softmax head, and the cross-entropy loss, is the same for every language model (following auto-regressive approach). The only thing that differs between model families is the function \(g_\theta\) that turns a prefix into the representation \(h_j\). The history of language modeling is largely the history of better answers to this question. Here we keep it at the level of intuition.

1. n-gram models (counting). The simplest approach is to assume that only the last \(n-1\) tokens matter, \(P(x_j\mid x_{<j})\approx P(x_j\mid x_{j-n+1},\dots,x_{j-1})\), and to store one distribution per context, estimated by counting exactly as in equation (14). Naive Bayes’ word model is the extreme case \(n=1\) (the “unigram” model). Unlike the chain rule, this truncation is an approximation, and it has real limits. The window is short, the number of possible contexts explodes as \(n\) grows (so most are never seen in training), and the model has no notion that “cat” and “dog” are similar words, so what it learns about one tells it nothing about the other.

2. Neural n-gram models (embeddings). Replace the table with a neural network. Each token is mapped to a learned dense vector (an embedding), the embeddings of the last \(n-1\) tokens are fed through the network, and the output is \(h_j\). Because similar words end up with similar vectors, what the model learns about “the cat sat” transfers to “the dog sat”. This is generalization, which the table could not offer. But the window is still fixed.

3. Recurrent networks (RNNs, LSTMs). Instead of a fixed window, an RNN reads the text one token at a time and carries along a state vector. At each step, the new state is a function of the previous state and the latest token, using the same weights at every step. In principle, the state can depend on the entire prefix. In practice there are real difficulties. The whole history must be squeezed into a single fixed-size vector, so older information fades. Gradients have to travel back through many steps, so learning long-range dependencies is hard. And since each state depends on the previous one, training cannot be parallelized across positions. LSTM and GRU variants add gates that ease the gradient problem but do not remove these limits.

4. Transformers. A Transformer does not compress the history into one vector. It keeps a representation for every earlier token, and lets each position look back at all of them directly through attention, which learns how much each earlier token matters for predicting the next one. Attention is causal: position \(j\) may look only at positions before it, which preserves exactly the dependence on \(x_{<j}\) that the factorization (18) requires. Yet all positions can still be computed in parallel in a single pass, which is what made training on huge corpora practical.

Key takeaway. A modern LLM is four pieces, each of which we have now seen:

  • a Transformer, the function approximator that turns a prefix into \(h_j\),
  • a softmax, which turns \(h_j\) into a categorical distribution over the next token,
  • the autoregressive factorization, which turns those conditionals into a distribution over whole texts,
  • maximum likelihood (cross-entropy), which learns the parameters.

It is not fundamentally “predicting text”. It learns \(P(\text{next token}\mid\text{previous tokens})\), and those conditionals together define \(P(\text{whole text})\), from which new text can be generated.

Revisiting the questions#

  1. What does “learning the distribution” mean in terms of what is optimized? We choose parameters that maximize the likelihood of the observed data, which approximately minimizes the KL divergence to the true distribution (equation 5). The discriminative approach maximizes the conditional likelihood \(\prod_i P(y_i\mid x_i;\theta)\), and the generative approach maximizes the joint likelihood \(\prod_i P(x_i,y_i;\theta)\).
  2. Why is logistic regression discriminative but Naive Bayes generative, when both produce \(P(y\mid x)\)? What makes a model generative is what it models and optimizes, not what it outputs at prediction time. Logistic regression parameterises \(P(y\mid x)\) directly and maximizes its likelihood. Naive Bayes parameterises \(P(x\mid y)\,P(y)\) and maximizes the joint likelihood, and only afterwards derives \(P(y\mid x)\) through Bayes’ rule.
  3. How can generative models produce new inputs but discriminative models cannot? Only a generative model has a distribution over inputs. We drew a label from the prior and then words from that class’s word distribution to produce a new email. A discriminative model only describes labels given inputs.
  4. An LLM predicts the next token given previous tokens, which looks like classification at each step. So how is it generative? Each next-token prediction is a classifier, but the quantity maximized is the likelihood of the whole text, \(\prod_i\prod_j P(x_{i,j}\mid x_{i,<j};\theta)\), which is a joint distribution over inputs. Every token is a label at its own position and part of the input at later ones, so the model learns a distribution over inputs and can score and sample them.

Appendix#

Short recaps of the background used above. Each entry is deliberately brief.

Appendix A: Probability recap#

  • Joint, marginal, conditional. The joint \(P(x,y)\) is the probability of both values together. The marginal is obtained by summing out the other variable, \(P(x)=\sum_y P(x,y)\) (an integral if \(y\) is continuous). The conditional is \(P(y\mid x)=P(x,y)/P(x)\), defined when \(P(x)>0\).
  • Product rule. \(P(x,y)=P(y\mid x)\,P(x)=P(x\mid y)\,P(y)\).
  • Bayes’ rule. Equate the two forms of the product rule and divide: \(P(y\mid x)=\dfrac{P(x\mid y)\,P(y)}{P(x)}\).
  • Chain rule. For any sequence of variables, with no assumptions at all: \(P(z_1,\dots,z_m)=\prod_{j=1}^{m}P(z_j\mid z_1,\dots,z_{j-1})\).
  • Independence. \(a\) and \(b\) are independent if \(P(a,b)=P(a)\,P(b)\). They are conditionally independent given \(c\) if \(P(a,b\mid c)=P(a\mid c)\,P(b\mid c)\).
  • Mass vs density. For discrete variables \(P\) is a probability. For continuous variables it is a density. The formulas in this post hold for both, with sums replaced by integrals.

Appendix B: i.i.d. sampling#

“Independent and identically distributed” means each example is drawn independently, and all from the same distribution. The consequence we use is that probabilities of the whole dataset factor into per-example probabilities: \(P(D)=\prod_i P(x_i,y_i)\), and for labels given inputs, \(P(y_1,\dots,y_n\mid x_1,\dots,x_n)=\prod_i P(y_i\mid x_i)\).

Appendix C: Bernoulli, categorical, and multinomial distributions#

  • Bernoulli(\(p\)): one yes/no trial. \(P(y)=p^{\,y}(1-p)^{1-y}\) for \(y\in\{0,1\}\).
  • Categorical(\(\phi_1,\dots,\phi_K\)): one draw from \(K\) possible outcomes, where outcome \(k\) has probability \(\phi_k\) and \(\sum_k\phi_k=1\).
  • Multinomial: the counts \((t_1,\dots,t_K)\) of each outcome after \(m\) independent categorical draws: \(P(t_1,\dots,t_K)=\dfrac{m!}{t_1!\cdots t_K!}\prod_k\phi_k^{t_k}\).
  • Binomial: the number of successes in \(m\) independent Bernoulli trials that all share the same \(p\).

Appendix D: Likelihood, log-likelihood, and MLE#

A probability fixes the parameters and varies the outcome. Over all possible outcomes it sums (or integrates) to \(1\). A likelihood uses the same formula but fixes the observed data and varies the parameters: \(L(\theta)=P(D;\theta)\). It does not sum to \(1\) over \(\theta\). For example, a coin with heads-probability \(\theta\) that lands heads once has \(L(\theta)=\theta\), and \(\int_0^1\theta\,d\theta=\tfrac12\neq 1\).

Maximum likelihood estimation picks the \(\theta\) with the highest likelihood. In practice we maximize the log-likelihood \(\ell(\theta)=\log L(\theta)\) instead. The log turns a product into a sum (easier to differentiate, and no numerical underflow), and because the log is increasing, the maximizing \(\theta\) is unchanged.

Appendix E: Entropy, cross-entropy, and KL divergence#

For two distributions \(p\) and \(q\) over discrete outcomes (natural log throughout): (assume \(p\) is the true distribution and \(q\) is the model’s distribution)

\[H(p,q)=-\sum_z p(z)\log q(z)\ \ (\text{cross-entropy}),\qquad H(p)=H(p,p)\ \ (\text{entropy})\]

\[\mathrm{KL}(p\,\Vert\,q)=\sum_z p(z)\log\frac{p(z)}{q(z)}=H(p,q)-H(p)\]

KL divergence is always \(\geq 0\), equals \(0\) exactly when \(p=q\), and is not symmetric. If \(p\) is fixed, \(H(p)\) is a constant, so minimizing \(\mathrm{KL}(p\,\Vert\,q)\) over \(q\) is the same as minimizing the cross-entropy \(H(p,q)\). For binary labels, the average cross-entropy between the true label and the model’s probability is the binary cross-entropy loss, \(-\frac1n\,\ell(\theta)\) in equation (8).

Appendix F: Lagrange multipliers and concavity#

To maximize \(g(\phi)\) subject to a constraint such as \(\sum_k\phi_k=1\), form the Lagrangian \(\mathcal{J}(\phi,\lambda)=g(\phi)+\lambda\big(1-\sum_k\phi_k\big)\). Set all partial derivatives to zero. The derivative with respect to \(\lambda\) simply returns the constraint, and the others give \(\phi\) in terms of \(\lambda\). Then use the constraint to solve for \(\lambda\).

A function is concave if the line segment between any two points on its graph lies on or below the graph. \(\log\) is concave, and a non-negative weighted sum of concave functions is concave. For a concave function with linear constraints, any stationary point is a global maximum.

Appendix G: MAP estimation and the Dirichlet prior#

MLE maximizes \(P(D\mid\theta)\). MAP (maximum a posteriori) estimation maximizes \(P(D\mid\theta)\,P(\theta)\), where \(P(\theta)\) is a prior that encodes beliefs about the parameters before seeing data. A symmetric Dirichlet(\(\alpha\)) prior over a categorical distribution has density proportional to \(\prod_k\phi_k^{\alpha-1}\). The MAP estimate (for \(\alpha\geq 1\)) is

\[\phi_k=\frac{N_k+\alpha-1}{M+K(\alpha-1)}\]

where \(K\) is the number of outcomes. So the prior acts like \(\alpha-1\) extra “pseudo-counts” per outcome. Setting \(\alpha=2\) adds exactly one pseudo-count per word, which gives equation (16). This is often called “add-one” smoothing, and it is the source of a common confusion: “add-one” refers to the pseudo-count, while the corresponding Dirichlet parameter is \(\alpha=2\).

Appendix H: Softmax and multiclass logistic regression#

For \(K\) classes with scores \(z_1,\dots,z_K\), the softmax turns scores into a categorical distribution:

\[\operatorname{softmax}(z)_k=\frac{e^{z_k}}{\sum_{k'=1}^{K}e^{z_{k'}}}\]

All outputs are positive and sum to \(1\). Adding the same constant to every score does not change the output. Multiclass logistic regression uses \(z_k=w_k^\top x+b_k\) and trains by maximum likelihood, which is categorical cross-entropy. With \(K=2\) the softmax reduces to the sigmoid: \(\frac{e^{z_1}}{e^{z_0}+e^{z_1}}=\sigma(z_1-z_0)\), so binary logistic regression has \(w=w_1-w_0\) and \(b=b_1-b_0\). The gradient of the loss with respect to the scores is “predicted probabilities minus the one-hot label”, for any \(K\).
